# Синтетические контрактные примеры

Все JSON в этой папке созданы командой для проверки формата и разработки UI. Это не данные организаторов, не результаты вызова модели и не человеческая эталонная разметка качества. В интерфейсе разработки их использование требует видимой отметки mock-режима.

`manifest.json` сопоставляет каждый пример схеме из `contracts/openapi.json`. Подкаталоги с дополнительными наборами имеют собственный manifest; общая проверка охватывает их рекурсивно. Проверка запускается через `make check`. Три языка и звонок с отсутствующим аудио покрывают форму данных; знание языка или доступ к настоящей записи этим не подтверждаются.

Основной связанный пример: `conversation.response.json` / `transcript.snapshot.json` → `checklist-version.response.json` → `provider.response.json` → `evaluation.completed.json` → `appeal.open.json` → `decision.response.json`. UUID и message ID согласованы. Пользовательский чек-лист содержит четыре новых ID: веса 40/60/20, N/A у третьего критерия и отдельный флаг. Исходный итог 70; после синтетического override — 100 при неизменном original. Неизвестное usage и стоимость — null. `request_count=1` иллюстрирует формат, не факт реального вызова.

`checklist.initial.json` содержит восемь исходных критериев реализованного seed C-01. Источник смысла критериев — `docs/SCORING.md`. Секции — группировка команды, не правило организаторов.

[workspace](workspace/README.md) — расширенные synthetic wire-примеры для redesign: 120 сообщений, 12/13 критериев, текущая и архивная версии, N/A, независимые флаги и неизменяемая история решений. Они используются только явно обозначенными тестами, не добавляются в seed и не включают живой AI.

Экспорты JSON Schema проверяют структуру, типы и локальные ограничения. Уникальность ID/ступеней, принадлежность сообщений/версий, арифметику и сохранность реальной истории должны проверять реализации C/N и их тесты.
