# HULK'S FAMILY — Conversation Quality Analytics

Прототип для хакатона Freedom Broker: оценка работы оператора по диалогу, объяснения с доказательствами, редактируемый чек-лист и пересмотр оценки через апелляцию.

**Статус на 7 ноября 2026 года:** создан серверный каркас с настройками, SQLite health-check, безопасными ошибками и стартовой CI; подготовлены проверяемый общий контракт и синтетические примеры. Интерфейс, бизнес-маршруты, миграции, worker и AI-анализ ещё не реализованы. Полный статус — в [роадмапе](docs/ROADMAP.md).

## С чего начать участнику или AI-агенту

1. Прочитать [AGENTS.md](AGENTS.md).
2. Найти свою ветку и задачи в [роадмапе](docs/ROADMAP.md).
3. Прочитать [архитектуру](docs/ARCHITECTURE.md), [API-контракт](docs/API_CONTRACT.md) и [правила расчёта](docs/SCORING.md).
4. Использовать соответствующее задание из [инструкций для агентов](docs/AGENT_TASKS.md).
5. Обновлять роадмап вместе с реализацией, если изменились статус, зависимости, объём работы или техническое решение.

## Предлагаемый стек

- Интерфейс: React, TypeScript, Vite; результат сборки — HTML/CSS/JavaScript.
- Сервер: Python, FastAPI, Pydantic, SQLAlchemy, Alembic.
- Хранение: SQLite для одного экземпляра демонстрационного сервера.
- AI: OpenAI Responses API и Structured Outputs за заменяемым интерфейсом провайдера.
- Проверки: pytest, Playwright и отдельное сравнение оценок с ручной разметкой.
- Запуск: Docker Compose после реализации инфраструктуры.

Модель выбирается по проверке на RU/KZ/EN. Название модели в `.env.example` — непроверенный начальный кандидат: доступность для аккаунта и качество ещё предстоит подтвердить. Это выбор команды, а не требование организаторов.

## Запуск серверного каркаса

Требуются Python 3.12–3.14 (основная версия 3.13), [uv](https://docs.astral.sh/uv/getting-started/installation/) и Make. Команды выполняются из корня репозитория:

```bash
cp .env.example .env
make setup
make check
make api
```

Ключи для health-check не нужны. В другом терминале:

```bash
curl --fail http://127.0.0.1:8000/health
```

Ожидаемый ответ — `{"status":"ok"}` после реального `SELECT 1` в SQLite. БД создаётся в `data/private/cqa.sqlite3`; относительный путь всегда считается от корня репозитория. Таблиц приложения пока нет: миграции/seed — C-01. При ошибке соединения health возвращает 503. Реализованные маршруты видны в [локальной документации API](http://127.0.0.1:8000/docs); сейчас это только `/health`.

Если Make не установлен, эквиваленты: `uv sync --project backend --locked`, `uv run --project backend --locked pytest backend/tests` и `uv run --project backend --locked uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log`. Lint/форматирование и проверка экспортов перечислены в `Makefile`. Обычные access-логи отключены, чтобы query string не попадал в журнал; приложение пишет статус и длительность без URL/тела/исключения.

`CQA_ALLOWED_ORIGINS` — список HTTP origins через запятую, по умолчанию `http://localhost:5173`. Frontend создаётся Артёмом в R-01; согласованный dev-порт — 5173, backend — 8000. Для CI версия Python передаётся через `UV_PYTHON`.

Для backend подготовлен отдельный контейнер с постоянным томом SQLite:

```bash
docker compose -f compose.api.yaml up --build --wait
```

Это только API. Локальный Docker daemon недоступен, но сборка, запуск Compose и HTTP health-check успешно проверены в [GitHub Actions для 194312e](https://github.com/abilkhayrbigali-design/HULK-S_FAMILY_REPO/actions/runs/42366645190). ## Логи для диагностики

Все участники и AI-агенты обязаны добавлять безопасные логи своей реализации по [общей инструкции](docs/LOGGING.md). Требование закреплено в `AGENTS.md` и заданиях каждого участника.

Сервер выводит логи в терминал; контейнер — в `docker compose -f compose.api.yaml logs -f api`. Для сохранения локального журнала в игнорируемой папке:

```bash
mkdir -p artifacts
make api 2>&1 | tee artifacts/api.log
```

`cqa.requests` пишет одну запись на запрос, включая CORS preflight: статус, длительность и безопасный код ошибки. Успех — INFO, 4xx — WARNING, 5xx и сбой после начала ответа — ERROR. При `CQA_LOG_LEVEL=ERROR` серверные ошибки по-прежнему видны. Примеры формата:

```text
ERROR cqa.requests request status=503 duration_ms=2 error=DATABASE_UNAVAILABLE
ERROR cqa.errors error=DATABASE_UNAVAILABLE locations=backend/app/main.py:123
```

Строка 123 иллюстрирует формат; фактическое место берётся из текущего кода. `cqa.errors` показывает безопасный код и до 16 мест `файл:строка` внутри репозитория для внутреннего исключения или сбоя БД. Если поток/фоновая задача упали после отправки заголовков, в журнале может остаться `status=200` с `error=INTERNAL_ERROR` и уровнем ERROR. Тексты исключений, исходные строки Python, локальные переменные, тела запросов, URL и ключи в эти записи не включаются. Для новых обработчиков используйте `error_response(..., request=request)` и при необходимости `log_internal_error` из `app.diagnostics`; передавайте фиксированный код, а не текст исключения.

## Данные и доступ

Проверенный DEV API содержит 65 диалогов: 60 чатов и 5 транскриптов звонков; 35 RU, 15 KZ, 15 EN. Для звонков есть ссылки на аудио. Эталонных оценок в полученном ответе нет.

Подписанная ссылка организаторов хранится только в локальном `.env` на сервере. Она не должна попадать в Git, интерфейс или логи. Настройки из [.env.example](.env.example) читает `backend/app/config.py`; секретные поля скрыты в repr. Пустые ключ/URL допускают старт каркаса; операции AI/импорта обязаны вызвать `require_llm`/`require_dataset` и вернуть 503, если настройки отсутствуют. Сам импорт и AI-адаптер ещё предстоит реализовать.

В публичный репозиторий добавляются только собственные синтетические примеры. Исходные диалоги, аудио и ручная разметка хранятся в игнорируемом `data/private/`.
