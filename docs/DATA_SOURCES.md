## Проверка DEV-источника

Выполнен один read-only GET без повторов и перенаправлений: HTTP 200, 65 диалогов,
как и заявлено в guide. В фактическом payload нет labels, answers, scores,
ground_truth или human_annotation_source. Есть диалоги и их метаданные;
это материал для оценки и ручной разметки, а не выданные эталонные ответы.
Явных признаков real/synthetic в метаданных нет; происхождение сверх названия
организаторского DEV-набора не утверждается.

JSON сохранён только локально: `data/private/dev-dataset.json`, права 600,
Git игнорирует файл. Ссылка с подписью, аудиоссылки, контакты, внешние ID
и тексты переписки в этот документ не включены. Данные не импортированы
в рабочую БД и не отправлялись OpenAI или Figma.

## Следующий шаг для точности

Нужно независимо разметить часть DEV-набора человеком по зафиксированному
чек-листу, заранее выделив tune/holdout и охватив RU/KZ/EN, N/A и нарушения.
Пустая локальная заготовка `data/private/labels.template.json` имеет
`annotation_source=pending_human` и намеренно не является валидным GT.
Протокол, формат и offline-метрики — в [BENCHMARK.md](BENCHMARK.md).

Эталоны организаторов для скрытых контрольных диалогов в обследованных
источниках не опубликованы. Разовая проверка API приложения описана в
[LIVE_PILOT.md](LIVE_PILOT.md); её разрешение использовано. Новые платные
вызовы для получения предсказаний требуют отдельного разрешения.
