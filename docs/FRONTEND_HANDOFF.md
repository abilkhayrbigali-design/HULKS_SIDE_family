# Передача интерфейса CQA

Артём, задачи R-01—R-09. Реализация находится в `frontend/`; сервер, AI и расчёт принадлежат соответствующим участникам. Код и история остаются только в рабочем HULKS_SIDE_family. Репозиторий-пример не изменяется.

## Запуск и сборка

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
npm --prefix frontend run check
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

Dev: `http://127.0.0.1:5173`, proxy `/api` → `http://127.0.0.1:8000`. API относительный `/api/v1`. Production output: `frontend/dist`. Контракт интеграции: раздачу этого каталога на одном origin подключает Абулхаир в FastAPI; серверная реализация не входит в коммиты ветки frontend. Приложение использует hash-навигацию `#/dialogues`, `#/dialogues/{id}?evaluation={id}` и `#/checklists`, поэтому серверный SPA fallback не требуется. Внешние шрифты, телеметрия и ключи в frontend не добавлены.

Для Playwright автоматически используется `/usr/bin/chromium`, если он существует. Можно задать `CQA_CHROMIUM_PATH`; иначе нужен установленный штатный браузер Playwright (`npm --prefix frontend exec playwright install chromium`). CI должен предоставить браузер перед E2E. Vite запускается самим Playwright, если порт 5173 свободен; в обычной локальной сессии существующий сервер переиспользуется.

## Реализованные сценарии

- Список с серверными фильтрами RU/KZ/EN, каналом, группой, пагинацией и поиском ID на текущей странице. Импорт группы, массива JSON, `records` или оболочки `data.records`; собственный учебный пример загружается только отдельной явной кнопкой.
- Карточка сообщений с ID, исходными ролями, временем и содержимым. При выборе сохранённой оценки загружаются именно её версии транскрипта и чек-листа. Архивный снимок помечается отдельно. Доказательства открывают и выделяют включительный диапазон; текст берётся из транскрипта. Запись звонка открывается без передачи referrer; перемотка по неподтверждённым timestamp не выполняется.
- Выбор любой сохранённой версии чек-листа и создание нового запуска. Polling каждые 2 секунды с остановкой на завершении или сетевом отказе; повтор чтения и новый запуск доступны явно. Исходный и финальный балл, N/A, флаги, секции, версия, revision, параметры и история запусков отображаются отдельно.
- Динамический редактор binary/scale/flag, положительных весов, ступеней, инструкций, разделов и N/A. Критерии добавляются/удаляются; ID сохраняется при редактировании. Новое сохранение создаёт версию. 409 сохраняет черновик и позволяет обновить базовый номер без замены ввода. На время POST поля заблокированы, чтобы правка после отправки не считалась сохранённой. Загружаются все страницы чек-листов, включая созданные после первых 100.
- Апелляции с комментарием, подтверждением или override, причиной и доказательствами. Конфликт revision сохраняет поля; явное обновление получает актуальную ревизию без размонтирования формы. История показывает неизменяемый `decision.result` отдельно от текущего ответа. Во время сохранения комментарий и решение заблокированы; исходная оценка не перезаписывается.
- Адаптивная навигация, видимый фокус, keyboard skip-link, modal focus trap и Escape с возвратом к кнопке открытия; длинные RU/KZ/EN строки не исполняются как код.

Фактически выполнены TypeScript check, Vite production build, **7 Vitest** и **13 Playwright E2E** на собственных синтетических фикстурах. Родительская интеграционная проверка дополнительно создала пользовательский чек-лист и v2, затем открыла неизменённую v1. **Живых OpenAI вызовов нет по инструкции пользователя. Доступность gpt-6-luna и точность модели этими проверками не подтверждены.**

Локальные screenshots: `frontend/test-results/cqa-result.png` (явно синтетическая оценка) и `frontend/test-results/cqa-mobile.png`; копии для передачи в игнорируемом `artifacts/`. Приватные диалоги организаторов в тестах не используются.

## Безопасные ошибки и журнал

Общий API-клиент пишет только `event=ui_operation_failed status=<number> error=<allowlisted_code>`. 4xx → `console.warn`, 5xx/соединение → `console.error`. Тексты ответов сервера, исключений, payload и URL не выводятся; незнакомые коды становятся API_ERROR. Polling не создаёт отдельный лог при каждом успешном чтении, при отказе останавливается.

Воспроизводимый сценарий: запустить сервер без OPENAI_API_KEY, импортировать учебный диалог и нажать «Оценить диалог». В UI — понятное сообщение AI_NOT_CONFIGURED, в консоли — фиксированная строка с503. Vitest и E2E также подставляют секретные маркеры в сообщения ошибок и подтверждают их отсутствие в пользовательском сообщении и консоли. Ожидаемые коды AI_AUTHENTICATION_FAILED, AI_TIMEOUT, AI_REFUSED и AI_INCOMPLETE имеют отдельные понятные объяснения.

Q-01 выполняет отдельный gpt-6.1-sol/xhigh; окончательный отчёт с base/head SHA передаётся интегратору вне нового коммита. Первичный reviewer выявил четыре P2: черновик апелляции после refresh409, immutable decision history, ввод во время checklist save и initial Shift+Tab в modal. Они исправлены с регрессиями; тот же pending-submit случай устранён в обеих формах апелляции.

## Enterprise redesign — R-06—R-09

Визуальная основа — editable Figma [CQA / Audit workstation](https://www.figma.com/design/vEvqJlR06dJtBMkgZUQRwl?node-id=3-103), узел `3:103`; исходные пропорции 1440×900: header56, rail56, queue264, transcript700, audit420. Перед первым `get_design_context` полностью прочитан `figma-design-to-code/SKILL.md`, передан `skillNames=figma-design-to-code`, получены reference code и screenshot базового frame. Повторный code-context заполненных дочерних панелей заблокирован лимитом Figma Starter MCP. Не заявляется получение полного финального code context; используются уже полученная геометрия, точные A tokens и его экспортированный PNG для визуальной сверки. Данные реального пользователя в Figma не передавались.

Официальный shadcn MCP действительно запущен родителем как stdio JSON-RPC процесс через `npx shadcn@4.23.0 mcp`; serverInfo `shadcn/1.0.0`. Выполнены `initialize`, `tools/list`, затем `get_project_registries`, `search_items_in_registries`, `view_items_in_registries`, `get_item_examples_from_registries` и `get_add_command_for_items` в frontend этого проекта. Registry `@shadcn`; просмотрены Button/Badge/Tooltip/Sheet/ScrollArea/Resizable/Separator/Tabs, получен реальный TSX resizable-demo. Исходный локальный receipt родителя — `/tmp/cqa-shadcn-search-results.json`; это проверяемый результат текущей сессии, а не новая встроенная конфигурация Codex. Глобальный Codex config не менялся. CLI `add` версии4.23.0 затем установил выбранные исходники, а не подменял MCP. Upstream использует официальный `cn`0.5.2, `radix-ui`1.8.1 и `react-resizable-panels`4.19.1. Новые прямые зависимости зафиксированы точными версиями; Tailwind4.3.5 подключён без общего preflight. Inter Variable5.3.0 со всеми нужными RU/KZ/EN subsets раздаётся локально.

Реализованы постоянная очередь, самый широкий центральный транскрипт и панель качества/решений. Dark — начальная тема; light переключается без перезагрузки. Импорт JSON/группы, фильтры, пагинация, динамический редактор, версии, сохранение и серверный расчёт сохранены. Критерии произвольные, а не ограниченные восемью. Каждая строка показывает исходный вес и нормализованный вклад /100; выбранное основание — исходный/применимый вес, объяснение и проверенные evidence. Partial scale выделяется amber с максимумом, pass — teal с иконкой, custom event flags — нейтрально, известный gross_errors — отдельно. Выбранная строка нейтральная, evidence зелёный.

Панели меняют ширину мышью и клавиатурой, вторичные панели сворачиваются. На ширине до1000px используются переключатели очереди/транскрипта/качества с теми же смонтированными компонентами. Неактивные и свёрнутые панели inert/aria-hidden, не рисуются и не оставляют скрытых Tab targets. Header-close возвращает видимый фокус; evidence имеет приоритет над восстановлением прокрутки. Правая панель целиком прокручивается даже при коротком окне и длинных review_reasons. Исходный и финальный баллы расположены рядом; действия проверяющего отделены от исходной AI-оценки. История показывает immutable decision.result, базовую и текущую ревизии раздельно.

Фильтры/поиск текущей страницы/пагинация сохраняются в sessionStorage собственной вкладки и переживают reload; тема и геометрия — в localStorage. Если storage недоступен, используются безопасные значения по умолчанию и память текущей навигации. Черновики обращений и решений находятся только в памяти, привязаны к evaluation/transcript/checklist+criterion либо immutable appeal ID, не записываются в storage/логи. Они сохраняются при переходах, смене темы и панелей, но перезагрузка страницы сбрасывает несохранённый черновик. Очистка после отправки сверяет submitted snapshot, чтобы запоздалый ответ не стёр новый ввод.

Generation guards связывают результаты загрузки/polling/создания запуска/решений с актуальными conversation+evaluation. Ответ A после перехода A→B→A не навигирует обратно к устаревшему запуску; late decision A не смешивает оценки A с транскриптом B; ошибка загрузки выбранного archive не скрывается за прошлым успешным результатом. Серверные записи при этом не удаляются и не отменяются локально.

После последней маленькой правки session filters/mobile labels повторены typecheck/unit/build и targeted reload/narrow сценарии. Независимый Sol/xhigh на функциональном f6ef226 повторил27E2E,50 backend contracts и6 собственных воспроизведений; обнаруженные P2 исправлены. Root/N/C независимо проверили real HTTP workspace на синтетических снимках, long120messages/12–13criteria, pinned snapshots/system evidence/immutable history, темы/resize/collapse/keyboard, actual bounds на узком экране и безопасные503. Root native CUA с настоящим FastAPI8000/пустым ключом проверил импорт→карточку→AI_NOT_CONFIGURED без созданной оценки. Финальные снимки независимого N QA находятся в thread-каталоге `workspace-qa/final-*.png`; копии собственных Playwright screenshots — в игнорируемом `artifacts/redesign/`.

Финальная визуальная проверка добавила resize-регрессию: перенос строк800→390px не должен уводить выбранное доказательство за экран. ResizeObserver сохраняет видимую реплику и смещение; доказательство удерживается только пока оно было видно. После ручной прокрутки к другой реплике resize сохраняет именно новую позицию чтения. Прокрутка при resize не забирает фокус у keyboard separator. Проверены actual viewport bounds, manual-scroll→resize и сохранение фокуса разделителя.
