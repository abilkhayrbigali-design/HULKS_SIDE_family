# Роадмап разработки

Версия 0.1 от 2026-11-07. Отсчёт часов ниже — от официального старта хакатона, а не от времени создания репозитория. Это оценка порядка работ; точное время старта в переданных материалах не задано.

**Обязательное правило для других AI: дорабатывайте этот роадмап, если во время реализации обнаружились недостающие задачи, неверные зависимости или необходимость изменить архитектуру. Обновляйте план вместе с кодом, сохраняйте историю и не отмечайте незавершённую работу готовой.** Подробный порядок — в [AGENTS.md](../AGENTS.md).

## 1. Цель и приоритеты

Основной результат: система действительно оценивает новые диалоги по выбранной версии чек-листа, даёт проверяемые объяснения и показывает точность, измеренную относительно ручной разметки команды. На скрытых 10 транскриптах организаторы сравнят ответы со своим Ground Truth.

- **P0:** оценка новых данных; RU/KZ/EN; настраиваемый чек-лист; верная арифметика; доказательства; апелляция и пересчёт; проверка точности; воспроизводимый запуск.
- **P1:** полезные дополнения после готовности P0, если остаётся время.
- **P2:** развитие после хакатона.

Нельзя заменять работу над точностью дополнительными функциями. Точная официальная формула сравнения с Ground Truth неизвестна.

## 5. Практика работы с Git

1. Участник клонирует репозиторий в свой каталог, делает `git fetch origin` и переключается на свою ветку.
2. До начала новой задачи синхронизирует свою ветку с актуальной `origin/main` обычным merge, сохраняя собственные изменения.
3. Работает небольшими коммитами в своей ветке и обновляет соответствующие строки роадмапа.
4. Отправляет ветку и PR в `main`. В описании: ID задач, результат, проверки, изменения контрактов/плана и ограничения.
5. Для каждого PR любого участника обязательна Q-01: отдельный агент `gpt-6.1-sol` / `xhigh`, проверка ошибок, логов и лишнего кода, исправления и повторный просмотр финального коммита по [CODE_REVIEW.md](CODE_REVIEW.md). Это относится и к документации/конфигурации. Создать PR можно до ревью; сливать до завершения проверки нельзя.
6. Абулхаир как интегратор объединяет совместимые изменения после проверок, сверяет отчёт Q-01, head SHA и CI. Другие участники получают обновлённый `main`. Отчёт другого PR или прежний статус DONE не заменяют текущую проверку.

Первичная база всех веток — коммит планирования. Создание ветки не означает назначения GitHub-прав конкретному аккаунту: доступы участников настраиваются отдельно, если их ещё нет. Имена аккаунтов Чингиза, Нурсултана и Артёма в текущем задании не переданы.

## 6. Как изменять план

При каждом изменении:

1. Описать обнаруженный факт, а не только предпочтение.
2. Исправить или добавить задачу своего участника с новым ID (`A-06`, `C-06`, `N-06`, `R-06` и далее).
3. Указать приоритет, зависимости, владельца и проверяемый результат.
4. Если меняется архитектура/API/арифметика — обновить соответствующий документ и `DECISIONS.md` в том же PR.
5. Добавить запись в журнал ниже. При конфликте сохранения плана объединить полезные изменения обеих сторон; статус подтверждается кодом/проверкой, а не более поздним временем редактирования.

Это требование распространяется и на последующие AI, которым участники передадут репозиторий. Роадмап можно уточнять автономно в пределах порученной задачи; нельзя молча расширять продукт или выдавать новую идею за правило организаторов.

## 7. Общая готовность к защите

- [ ] Новая установка запускается по README; данные сохраняются после перезапуска.
- [ ] DEV и другой group_id обрабатываются без изменения кода; пользовательский JSON тоже работает.
- [ ] RU/KZ/EN оценены; есть честный отчёт сравнения с ручной разметкой.
- [ ] N/A, шкалы, веса, секции и отдельные грубые нарушения рассчитаны корректно.
- [ ] Каждое доказательство открывает нужное сообщение/диапазон; доступна ссылка на запись звонка.
- [ ] Изменение и добавление критерия через UI реально влияет на новый запуск.
- [ ] Апелляция сохраняет исходный ответ и решение, итог пересчитывается без нового AI-вызова.
- [ ] Неверный API-ключ, таймаут, 429/5xx и невалидные данные дают понятную ошибку.
- [ ] Известны модель, число вызовов, задержка и примерная полная стоимость одной оценки.
- [ ] Нет секретов и исходных данных в Git; последние изменения плана соответствуют коду.
- [ ] Защита укладывается в 5 минут, финальный коммит записан к стоп-коду.

На старте эти пункты не выполнены. Их отмечают только по фактическим проверкам.

## 8. Открытые вопросы, не блокирующие начало

- Доступный AI-аккаунт, лимиты и бюджет: подтвердить до реального N-01; до этого можно делать схемы, арифметику и UI.
- Проверка ручной разметки KZ человеком, владеющим языком: организовать в N-03.
- Справочник тарифов/процедур компании: запросить при необходимости; не придумывать отсутствующие правила.
- Официальная формула сравнения с Ground Truth и контрольный group_id: учесть, когда организаторы сообщат.
- GitHub-аккаунты коллег: нужны только для выдачи прав на push, а не для создания их веток.
