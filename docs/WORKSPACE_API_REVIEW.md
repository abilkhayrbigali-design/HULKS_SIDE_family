## Два найденных P2 и повторная проверка

**Ошибка чтения выбранного запуска скрывала ошибку и оставляла прошлую оценку.**
На `f706dfa` открывался текущий run `...0032` с итогом100/13 критериями, затем
выбирался archived run `...0031` того же conversation. Для его GET возвращался
503 DATABASE_UNAVAILABLE. Из-за ready, учитывавшего только conversation.id и
loading, интерфейс оставлял100/13 под URL уже другого запуска; alert отсутствовал.

**Результат отложенного решения попадал в другой диалог.** На `f706dfa` POST
решения апелляции A удерживался до перехода к B. После ответа A callback
onUpdated заменял оценку B: при heading/URL B справа появлялись69.57/12 критериев
от A вместо100/13. Unmount дочернего Appeals не отменял callback родителя.

Оба случая переданы R с воспроизведением. На `6ffdc7f` проверка выполнена заново
из отдельного git archive, а не изменяемой рабочей копии с HMR:

```text

archive GET503: alerts=1, staleScore=0, rows=0   PASS
delayed decision A after switch B:
  heading/URL=B, score=100.00, rows=13          PASS
externalRequests=0                            PASS
```

Локальный preview работал на отдельном порту5179 и после проверки остановлен.
Dev-сервер R, его последующие правки и tracked-файлы не затронуты. Проверка не
объявляет последующие R-08/R-09 изменения проверенными автоматически.
