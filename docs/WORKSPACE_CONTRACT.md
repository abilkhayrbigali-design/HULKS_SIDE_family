# Сохраняемый контракт CQA workspace

Audit C-10 от 2026-11-08, исходная версия кода `8d4faad`. Трёхпанельный
workspace меняет представление очереди, переписки и оценки. Существующий API v0.1
покрывает эти сценарии; новые backend-маршруты, модели хранения и авторизация для
redesign не требуются. Источник wire-формата — [API_CONTRACT](API_CONTRACT.md),
runtime Pydantic/OpenAPI и `contracts/openapi.json`.

## Единый контекст выбранной оценки

При выборе диалога и запуска UI связывает четыре значения:
`conversation_id`, `evaluation.id`, `evaluation.transcript_version_id`,
`evaluation.checklist_version_id`. Нельзя смешивать последнюю переписку,
выбранную старую оценку и текущую редактируемую версию чек-листа.

| Панель или действие | Источник и правило |
| --- | --- |
| Очередь | `GET /conversations` возвращает текущие метаданные и краткий `latest_evaluation`. Он обозначает последний созданный запуск, который мог оценивать старую версию транскрипта |
| Выбранный запуск | `GET /evaluations/{id}`; проверить, что его `conversation_id` совпадает с выбранным диалогом |
| Переписка оценки | `GET /conversations/{conversation_id}?transcript_version_id={evaluation.transcript_version_id}`; без параметра сервер возвращает текущую версию |
| Правила оценки | `GET /checklist-versions/{evaluation.checklist_version_id}`, включая имена, шкалы и N/A. Определения сопоставляются по `criterion_id`, не по позиции массива |
| Новая оценка | `POST /evaluations` с conversation_id и выбранным checklist_version_id. Сервер фиксирует **текущую** версию транскрипта даже при просмотре архивной оценки |
| Новая версия правил | `POST /checklists/{id}/versions` с expected_version_number. Не изменяет старые оценки и их final |

Если версия отображаемой переписки отличается от `current_transcript_version_id`,
показывается признак архива. При быстрой смене элемента очереди/запуска старые
HTTP-ответы, polling и highlight не должны попадать в новый контекст. URL/hash с
evaluation ID должен переживать reload и возвращать тот же запуск.

ID `m0001` уникален только внутри версии транскрипта. Evidence разрешается по
связанной версии: message — одна существующая реплика, range — включительный
диапазон в её порядке. Текст берётся из `messages`, а не из придуманной цитаты.
Выделение, focus и scroll после смены оценки очищаются или вычисляются заново.
Роли client/bot/system сохраняются как контекст; оценивается оператор.
Время реплики — исходная строка, оно не устанавливает позицию аудиоплеера.

## Баллы, флаги и динамические критерии

`evaluation.original` — неизменный исходный результат, `final` — результат с
решениями апелляций. Веса, base_points, effective_weight, effective_points,
итоги и секции возвращает сервер. UI форматирует их до двух знаков и не
пересчитывает сохранённый final при выборе другого чек-листа или темы.

- `not_applicable` и answer=null исключают вес из знаменателя. Это не ответ
  false и не числовой ноль; вклад можно показать как «не применимо».
- У scale ответ принадлежит шкале сохранённого критерия; numeric 0 отличается
  от binary false. Начальные восемь критериев — seed, а не лимит интерфейса.
  Карточка, список, счётчик, редактор и формы апелляций работают с произвольными ID.
- `gross_error=true` — отдельный флаг, который не обнуляет итог. false означает,
  что нарушение не отмечено, null — что в выбранных правилах нет флага с ID
  `gross_errors`. Остальные flags не объединяются с ним через логическое OR.
- Завершённая оценка может иметь total=null, когда применимых балльных критериев
  нет; показывается no_applicable_reason, а не фиктивный 0 или failed.
- `sections[].name` может быть null. Такой раздел допускает нейтральную подпись.
  Run-level review_reasons относятся к исходному AI-запуску и остаются для аудита;
  текущие причины отдельных критериев находятся в final.criteria.

## Апелляции и проверяемая история

`GET /appeals?evaluation_id=...` содержит original, current и nullable decision.
**current меняется** при следующих решениях по оценке; это не снимок старого
решения. Историческая запись показывает `decision.result`, action, reason,
expected_revision и created_at. Ранее подтверждённый false остаётся в истории
после последующего override на true.

Открыто одно обращение на evaluation+criterion. POST решения передаёт текущую
`evaluation.revision` как expected_revision; revision относится ко всей оценке,
поэтому конфликт возможен и после решения другого критерия. Confirm фиксирует
текущий final-ответ, который уже мог отличаться от original. Override передаёт
полную applicability/answer/evidence по тем же снимкам. Ввод блокируется только
на время отправки; после 409 UI сохраняет черновик, обновляет контекст и предлагает
явный повтор. Успех подтверждается ответом сервера, а не локальной сменой badge.

Доступный audit timeline состоит из evaluation.created_at/completed_at,
appeal.created_at и decision.created_at/action/reason/result. Имён проверяющего,
назначенного сотрудника, running_at и ленты всех переходов API не возвращает.
Переключатель «оператор/проверяющий» является демонстрацией действий, не проверенной
личностью или системой прав доступа.

## Очередь, импорт и границы обещаний UI

| Возможность | Что действительно поддержано |
| --- | --- |
| Фильтры диалогов | Серверные language, channel, group_id; limit/offset |
| Серверный поиск, статус очереди, назначенный сотрудник, сортировка | В `/conversations` этих параметров нет. Нельзя выдавать локальный поиск текущей страницы за поиск всего набора или показывать фиктивное назначение |
| Фильтр статуса запусков | `/evaluations` поддерживает status и conversation_id; это список запусков, не серверный фильтр очереди диалогов |
| Пагинация | У всех списков items/total/limit/offset, максимум 100 элементов на страницу. История запусков/обращений и selector чек-листов должны загружать следующие страницы |
| Импорт JSON | POST /conversations/import с records; UI может извлечь data.records из организаторской оболочки. Ошибка одного элемента отклоняет весь импорт |
| Импорт группы | POST /datasets/import с group_id; подписанный адрес находится только на сервере |
| Повторный импорт | unchanged не создаёт дубликат; изменённый текст создаёт новую версию, старые оценки остаются на старой |

Список диалогов упорядочен по внутреннему ID, не по приоритету или SLA. Перезапуск
страницы и возвращение из карточки не должны без объяснения сбрасывать сохранённые
пользователем фильтры/страницу. Запусков, сообщений и критериев может быть больше
видимой высоты: панель прокручивается, данные не обрезаются первыми 8/100 элементами.

## Ошибки, повторы и происхождение результата

Queued/running/completed/failed — сохранённые статусы. Polling примерно раз в две
секунды относится только к выбранному незавершённому запуску. Ошибка polling не
становится failed или completed локально; доступен явный повтор чтения.

Без ключа POST /evaluations возвращает 503 AI_NOT_CONFIGURED до создания запуска.
Никакой успешный mock fallback не допустим. Сохранённый failed остаётся в истории;
«Повторить оценку» создаёт новый запуск, а не редактирует failed. Старый running
после рестарта становится failed/INTERRUPTED без автоматического платного повтора.
Известное provenance/usage может присутствовать и при failed, неизвестные токены
и стоимость остаются null. Model requested и model reported различаются.

Браузер показывает безопасное сообщение по фиксированному error.code. В консоли
только фиксированное событие/код/статус: не текст диалога, ответы модели, URL,
ключи, API payload или полное исключение. Темы и collapse панелей не меняют бизнес-
данные; synthetic fixtures используются только явно обозначенными тестами.

## Сценарии для проверки redesign

Расширенный связанный набор — [workspace fixtures](../data/fixtures/synthetic/workspace/README.md).
Он содержит 120 сообщений, все четыре роли, 12→13 критериев, разные текущие и
архивные снимки, N/A, отдельные flags, original/final и два исторических решения.
Формат проверяется общими схемами, арифметика — серверным Decimal-расчётом.

Обязательная целевая проверка нового React UI:

1. Открыть архивный evaluation по прямой ссылке при более новом current snapshot.
   Evidence и подписи правил должны остаться на архиве; новый запуск явно берёт current.
2. Быстро менять очередь/запуск во время polling и загрузки snapshots. Ни одна панель
   не должна показывать данные предыдущего выбора как данные нового.
3. Показать все 12/13 критериев и message m0120; открыть range118–120, system-контекст
   идентификации и пользовательский flag при gross_error=false.
4. Раздельно показать original65.22/final69.57 и старое confirm=false при current=true.
5. Сохранить импорт, фильтры/пагинацию, выбор версий, апелляции, 409 с черновиком,
   ошибки/no-key, новый запуск после failed, mobile collapse и клавиатурный focus.

Этот документ и synthetic fixtures не являются человеческим Ground Truth,
результатами живой модели или подтверждением её точности. До изменения ограничения
пользователя реальные OpenAI-запросы и расходы не выполняются.
