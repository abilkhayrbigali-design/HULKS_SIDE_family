# Демонстрация на 5 минут

Текущий режим — **offline, синтетический AI**. Живые OpenAI-вызовы запрещены
пользователем. Полную защиту с настоящей оценкой модели пока нельзя считать
готовой: нужны отдельное разрешение, проверка доступности модели и человеческая
разметка. Не называйте приведённые ниже баллы качеством модели.

Перед выступлением выполните `make setup`, `make build`, `make check`,
`make smoke`, `npm --prefix frontend run test:e2e` и
`npm --prefix frontend run test:e2e:backend`. Последняя команда воспроизводит
основной сценарий на настоящих API/SQLite/worker/SDK с in-memory MockTransport.

Для ручной offline-репетиции из корня:

```bash
uv run --project backend --locked python tools/offline_acceptance_server.py
```

Откройте [локальную репетицию](http://127.0.0.1:8019/). Сервер создаёт отдельную
временную БД, игнорирует `.env`, использует только синтетический ключ и транспорт
без сети. В карточке явно указано «Синтетическая оценка · тестовые данные».
Фиктивные usage и задержка этого режима не относятся к модели OpenAI.
При остановке временная БД удаляется; обычная БД приложения не затрагивается.
Закройте сервер Ctrl+C. Не запускайте его как production API.

| Время | Действие и сообщение жюри |
| --- | --- |
| 0:00–0:25 | Назвать задачу: оцениваем работу оператора по выбранным правилам, остальные роли дают контекст. Обозначить синтетическую границу репетиции. |
| 0:25–1:00 | «Импортировать диалоги» → «JSON-файл» → загрузить `data/fixtures/synthetic/import.request.json`. Это собственные синтетические данные. Выбрать новый диалог из очереди. |
| 1:00–1:45 | В блоке нового анализа выбрать чек-лист и v1, нажать «Оценить диалог». Показать сохранённый результат, N/A, исходные веса/вклады и отдельный флаг нарушения. По доказательству перейти к сообщениям. |
| 1:45–2:45 | Открыть «Чек-листы»: изменить инструкцию/вес, удалить один критерий, добавить собственный; сохранить v2. Вернуться к диалогу, выбрать v2 и запустить новую оценку. Показать новый состав критериев. |
| 2:45–3:45 | Выбрать старый запуск v1. Показать прежние правила и доказательства. Нажать «Оспорить», подать комментарий, отдельно «Рассмотреть как проверяющий», выбрать override и существующее доказательство, сохранить причину решения. |
| 3:45–4:25 | Показать новый final рядом с неизменным original. Обновить страницу, открыть историю; решение и исходный результат сохранились. Апелляция не вызывает AI. |
| 4:25–5:00 | Назвать фактические проверки и блокеры: отсутствие человеческой разметки/измеренной точности и live-прогона, private-репозиторий. Показать отчёт готовности, не демонстрировать ключи, URL организаторов или приватные данные. |

Без синтетического harness обычный `make api` при пустом ключе должен показывать
`AI_NOT_CONFIGURED`, а не успешную оценку. Это проверяется отдельным smoke-test.
После разрешения живого режима репетируйте тот же сценарий на обычном API;
зафиксируйте модель, все попытки, usage, задержку и стоимость только при известном
тарифе. Разрешение на live и на публичность репозитория — разные действия.
